Tech Stack

Vue 3 + Composition API

SPA framework. No Vuex/Pinia — state managed via composables (useFilters, useAuth, useI18n). Router via Vue Router 4.

Vite

Dev server and build tool. Frontend served on port 3000. Proxies API calls to the FastAPI backend on 8001.

Axios

All HTTP calls go through client/src/api.js — a centralized client with 13+ async methods mapping to backend endpoints.

FastAPI (Python)

REST API backend on port 8001. All routes in main.py. Input/output validated with Pydantic models. CORS open for development.

uv

Python package manager. Run backend with uv run python main.py. Dependencies declared in pyproject.toml.

In-Memory JSON

No database. JSON files in server/data/ loaded at startup via mock_data.py. All filtering happens in Python. Restart to reset state.

pytest

Backend test suite in tests/backend/ using FastAPI TestClient. Covers dashboard, inventory, and misc endpoints.

i18n (en / ja)

Custom useI18n composable. Supports English and Japanese. Currency auto-switches (USD/JPY). Locale persisted to localStorage.

Request Data Flow — Filtered List (e.g., Inventory)
1

User changes a filter

FilterBar dropdown emits update → useFilters composable updates a shared ref (e.g., selectedLocation).

2

Vue watcher fires

Each view watches filter state. Change triggers loadData(). getCurrentFilters() maps composable state → plain query param object.

3

api.js builds HTTP request

Axios appends query params: GET /api/inventory?warehouse=Tokyo&category=Sensors. Skips params set to "all".

4

FastAPI receives and filters

apply_filters() iterates in-memory list, applies warehouse (exact) and category (case-insensitive) predicates. No DB query needed.

5

Pydantic validates response

Each item is validated against the InventoryItem Pydantic model before serialization. Type mismatches surface as 422 errors.

6

Vue renders filtered data

Response stored in component ref. Computed properties derive display values (e.g., stock status). v-for renders the table rows.

Global Filter System

Filter State (useFilters composable)

  • selectedPeriod — months (2025-01…2025-12) or quarters (Q1-2025…)
  • selectedLocation — San Francisco, London, Tokyo
  • selectedCategory — Circuit Boards, Sensors, Actuators, etc.
  • selectedStatus — Delivered, Shipped, Processing, Backordered
  • Singleton refs — shared across all views without a store
  • getCurrentFilters() maps state → API query params

Filter Coverage by Endpoint

  • /api/inventory — warehouse, category only
  • /api/orders — all 4 filters (most complete)
  • /api/dashboard/summary — all 4 filters
  • /api/demand — no filters (global dataset)
  • /api/backlog — no filters (global dataset)
  • /api/spending/* — no filters (static JSON)
  • /api/reports/* — no filters (all orders aggregated)
